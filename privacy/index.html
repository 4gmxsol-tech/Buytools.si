Privacy Policy

See how BuyTools.si tools handle files, text, third-party code, model downloads and browser storage.

Last updated: November 7, 2026

Overview

BuyTools.si provides browser-based utilities. This policy describes the site's intended data handling. Individual tools can behave differently, so read the notice shown near a tool before using it.

Files and text you enter

Many image and text operations are designed to run locally in your browser and do not require an account. The CSV Viewer can read a selected .csv file up to 5 MiB with the browser File API; UTF-8 is used by default, UTF-8 and UTF-16 byte-order marks are recognized, and malformed text encodings are rejected rather than silently replaced. Parsing, filtering, sorting and export stay in the browser, and the selected file is not uploaded to a BuyTools.si processing endpoint. The JSON Formatter can read a selected UTF-8 .json file up to 5 MiB with the browser File API; parsing, formatting and minification stay in the browser, and the selected file is not uploaded to a BuyTools.si processing endpoint. The QR code generator is an exception: it sends the entered text or URL to an external image service to create the QR code. Other tools load code or model assets from third-party hosts when you start the relevant feature. Do not submit confidential documents, passwords, API keys or sensitive personal information unless you have verified the processing behavior described below.

Third-party code, model assets and browser storage

Third-party libraries are loaded on demand from your browser, rather than being downloaded on every page visit. These providers can receive ordinary connection metadata, such as your IP address, browser details, request time and requested resource URL.

  • QR code generator: the text or URL you enter is placed in the data query parameter of a request to https://api.qrserver.com/v1/create-qr-code/. The QR image is generated and returned by that provider. Do not use this feature for confidential text or private URLs.
  • PDF merge and split: the browser loads https://esm.sh/pdf-lib@1.17.1 when you run either operation. If the selected PDF files total more than 25 MiB, the tool asks for confirmation before requesting the library; cancelling prevents that request. This is a warning, not a hard limit. Continuing can use substantially more memory than the input files, especially on mobile devices. The current site code reads the selected PDFs in your browser and uses the library there; it does not send the PDF bytes to a BuyTools.si processing endpoint. The CDN receives the library request and standard connection metadata, not the selected PDF bytes.
  • Batch image compression and resizing: the browser loads https://esm.sh/jszip@3.10.2 when a batch operation proceeds to create the downloadable ZIP. If the selected images total more than 25 MiB, the tool asks for confirmation before requesting the library; cancelling prevents that request. Image processing and ZIP assembly are performed in the browser by the current site code; the CDN receives the library request, not the selected image files.
  • Images to PDF: the browser loads https://esm.sh/jspdf@4.2.1 when you create a PDF. If the selected images total more than 25 MiB, the tool asks for confirmation before requesting the library; cancelling prevents that request. The selected images are read and embedded in the browser; the current site code does not send their bytes to a BuyTools.si processing endpoint.
  • Background removal: the browser loads https://esm.sh/@imgly/background-removal@1.5.5. The library also downloads its WebAssembly and model assets from IMG.LY's default static asset host, staticimgly.com; the first download can be large and may be cached by the browser. In cold-cache Chromium CI tests on November 6, 2026 using library version 1.5.5, the standard isnet_fp16 model produced 27 model-host GET requests; 24 responses exposed Content-Length values totalling 94,553,445 bytes (about 90.2 MiB). The smaller quantized isnet_quint8 model produced 16 model-host GET requests; 13 responses exposed Content-Length values totalling 50,749,677 bytes (about 48.4 MiB). The sum of known-size responses was 46.3% lower for the smaller model in that run. These are measured lower bounds, not exact or guaranteed download sizes; some responses did not expose a length, and actual transfer varies by browser, cache and library assets. The comparison used generated synthetic images and checks file validity and alpha-mask agreement; it is not a real-photo quality benchmark. Quantization may change fine edges or small details, so review outputs before use. The current site code passes the selected image to the browser-side library and does not directly upload it to a BuyTools.si processing endpoint. The CI audit used a generated synthetic image and observed only GET requests with no external request body; this is evidence for the tested version and workflow, not a guarantee about future third-party code. Because third-party code and model assets are involved, do not treat this feature as a guaranteed offline workflow.

The exact library versions above describe the current site implementation and may change when a tool is updated. Third-party providers control their own infrastructure and privacy practices. Check your browser's network activity and the provider's current terms if you need to verify every request or have strict data-handling requirements.

The site stores your display-theme preference in browser local storage under the key buytools-theme. This is a local interface preference, not an account profile. Before the first background-removal model download in a tab, the tool asks you to confirm the possible cold-cache transfer. The decision is stored only for that tab session in sessionStorage under a model-specific key beginning buytools-background-removal-consent-v1:; accepting one model does not automatically accept the other. This is not an account identifier and is not sent to BuyTools.si. Declining stops before the IMG.LY library or model assets are requested.
