Observed background-removal runtime dependency graph

This snapshot records the package versions observed in a cold-context Chromium run on November 7, 2026. The entry package is version-pinned, but its CDN-transformed dependency graph resolves additional packages at runtime.

  • @imgly/background-removal — version 1.5.5. License: AGPL-3.0. Versioned npm package metadata.
  • onnxruntime-web — version 1.18.0. License: MIT. Requested by the upstream package as ~1.18.0; both the standard and WebGPU browser modules were observed. Versioned npm package metadata.
  • zod — version 3.25.76. License: MIT. Resolved from ^3.23.8; the browser trace loaded the Zod v3 module. Versioned npm package metadata.
  • ndarray — version 1.0.19. License: MIT. Resolved from ~1.0.0. Versioned npm package metadata.
  • iota-array — version 1.0.0. License: MIT. Runtime dependency observed beneath ndarray. Versioned npm package metadata.
  • is-buffer — version 1.1.6. License: MIT. Runtime dependency observed beneath ndarray. Versioned npm package metadata.
  • lodash — version 4.17.21. License: MIT. The upstream package source map contains this bundled component; no separate lodash browser request was observed. Versioned npm package metadata.

Model/WASM origin: the browser fetched resources.json and binary resources from staticimgly.com/@imgly/background-removal-data/1.5.5/dist/. In the same run, the standard isnet_fp16 model made 27 requests, 24 with known Content-Length values totalling 94,553,445 bytes. The quantized isnet_quint8 model made 16 requests, 13 with known lengths totalling 50,749,677 bytes (46.3% lower). These are lower bounds, not guaranteed transfer totals.

Evidence: Chromium workflow run 42413597856 and the versioned runtime baseline. The browser workflow now records SHA-256 response hashes for observed ESM modules and model/WASM resources in a downloadable CI artifact.

This is a runtime-observed inventory, not a complete SBOM. The ONNX Runtime package declares additional dependencies (flatbuffers, guid-typescript, long, onnxruntime-common, platform and protobufjs) that are bundled into its delivered module and are not separately resolved by the browser request trace. Their exact bundled versions and license evidence remain open. CI hashes are audit evidence only: the current browser imports do not enforce Subresource Integrity or verify hashes at runtime.

Security advisory context: Zod 3.25.76

GitHub's GHSA-mrhx-c7xc-m3w5 advisory currently lists Zod versions below 4.6.6 as affected. The associated CVE record was rejected by its CNA on October 28, 2026; its rejection rationale says the described memory growth scales with input already allocated by JSON parsing and depends on missing request-size limits. In this integration, Zod validates the fixed configuration object built by the site, while the selected image is passed separately as a Blob. No attacker-controlled array-validation path was identified. Treat this as a monitored, disputed advisory—not a confirmed exploitable BuyTools vulnerability—and do not force Zod 4 into the upstream package without a compatibility migration.
