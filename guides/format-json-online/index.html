What is JSON formatting?

JSON (JavaScript Object Notation) is a text-based data format used to exchange structured information between applications, web services and APIs. A JSON formatter adds indentation and line breaks so objects and arrays are easier to inspect. Formatting improves readability; it does not repair invalid syntax or change the underlying values.

A minifier does the opposite: it removes optional whitespace from valid JSON. This can make a payload more compact for storage or transfer, while the formatted version is usually easier for developers to debug.

How to format a JSON string

A JSON string is text that represents a JSON value, such as an object or array. To format it, the text must first contain valid JSON syntax. Paste the complete string into the online JSON formatter, choose Format, and copy the indented result. If validation fails, correct the reported syntax issue before formatting.

For JavaScript developers, the equivalent operation is to parse the string and serialize the value with indentation:

const jsonText = '{"name":"Ada","active":true,"roles":["admin","editor"]}';
const formatted = JSON.stringify(JSON.parse(jsonText), null, 2);
console.log(formatted);

JSON.parse() rejects invalid JSON. The third argument to JSON.stringify() sets the indentation width; 2 produces two-space indentation. This changes whitespace, not the represented data.

How to check JSON syntax online

Use a JSON syntax checker when an API response, configuration file or pasted JSON string will not parse. Paste the entire document into the validator and select Validate. A valid result confirms that the text follows JSON syntax; an error result gives you a starting location to inspect. Check the surrounding line as well, because a missing comma or quote can cause the parser to report a later character.

Valid JSON example

This is a valid JSON object containing strings, a number, a Boolean, an array and a nested object:

{
  "project": "BuyTools",
  "active": true,
  "version": 2,
  "features": ["format", "validate", "minify"],
  "owner": {
    "team": "engineering",
    "contact": null
  }
}

JSON values can be objects, arrays, strings, numbers, true, false or null. Property names and string values must use double quotes.

Invalid JSON: common mistakes

1. Single quotes

// Invalid JSON
{ 'name': 'BuyTools' }

// Valid JSON
{ "name": "BuyTools" }

2. Trailing commas

// Invalid JSON
{ "name": "BuyTools", }

// Valid JSON
{ "name": "BuyTools" }

3. Missing commas or colons

// Invalid JSON
{ "name": "BuyTools" "active": true }

// Valid JSON
{ "name": "BuyTools", "active": true }

4. JavaScript values and comments

Standard JSON does not support comments, undefined, functions, NaN or Infinity. Remove comments and convert values to supported JSON types before validating.

How to validate JSON and locate syntax errors

JSON validation checks the document against JSON syntax rules. Paste the text into the online JSON validator and choose Validate. If the input is valid, the tool confirms that no syntax errors were found. If parsing fails, inspect the reported line and column, then check the surrounding quotes, commas, colons and brackets.

  • Unexpected end of input: check for a missing closing brace, bracket, quote or value.
  • Unexpected token: inspect the character at or near the reported position.
  • Property name error: make sure object keys use double quotes.
  • Comma or delimiter error: check separators between properties and array items, and remove trailing commas.

Error wording and position details can vary by browser because the page uses the browser's built-in JSON parser. Treat the reported location as a starting point and inspect nearby characters too.

JSON syntax validation vs JSON Schema validation

JSON syntax validation checks whether text follows JSON grammar: property names and strings use double quotes, separators are in the right places, brackets match, and values use supported JSON types. That is different from checking whether the data has the fields and value types an application expects.

For example, this is syntactically valid JSON:

{
  "id": "42",
  "active": "yes"
}

An API contract that requires id to be an integer and active to be a Boolean would still reject those values. A document can therefore parse as valid JSON and still fail an application's schema or business rules.

The BuyTools.si JSON Formatter checks JSON syntax only. It does not validate JSON Schema, required fields, expected value types or an API contract. Use the schema validator defined by your API or application to check those constraints. The JSON to TypeScript converter can generate a starting type from sample data, but generated types are not runtime validation.

Formatted JSON vs minified JSON

Use formatted JSON when reading API responses, reviewing configuration files or debugging nested data. Use minified JSON when compact output is useful. Both represent the same data when produced from the same valid input; minification only removes unnecessary whitespace.

Is it safe to use an online JSON formatter?

For public or non-sensitive examples, a browser-based formatter is convenient. Never paste passwords, private customer records, access tokens, API keys or production secrets into an online tool unless you have verified its data handling. JSON formatting FAQs

How do I format a JSON string?

Paste the complete JSON string into a formatter and select Format. The string must be valid JSON first; if it is not, use validation diagnostics to fix the syntax before formatting.

How do I format a JSON file?

Open the JSON Formatter, choose a local UTF-8 .json file up to 5 MiB or paste its contents, then select Format. Choose Download .json to save the formatted result directly, or Copy output to copy it. Keep the original until you have verified the new file.

Can I open a JSON file directly?

Yes. Select a local UTF-8 .json file up to 5 MiB. The browser reads it locally; files larger than 5 MiB are rejected before reading. You can also paste text. The file is not uploaded to a BuyTools.si processing endpoint.

How can I check JSON syntax online?

Paste the complete object or array into a JSON validator and select Validate. Check any reported line and column, then inspect nearby quotes, commas, colons and brackets.

How do I check if JSON is valid?

Paste the complete document into a JSON validator and run Validate. A valid document follows JSON syntax rules, including double-quoted strings and property names, correct separators and matching braces and brackets.

Does a JSON formatter fix invalid JSON?

No. A formatter can make valid JSON easier to read, but invalid syntax must be corrected first. Use the validation error and its line context to locate the problem.

Does formatting change the JSON data?

Formatting changes whitespace and indentation only. It preserves the represented values and structure when the input is valid JSON.

What is the difference between JSON and a JavaScript object?

JSON is a text data format with stricter syntax. For example, JSON requires double quotes around property names and strings, and it does not allow comments, functions or undefined values.

Does valid JSON mean it matches my API schema?

No. Valid JSON confirms syntax only. This formatter does not validate JSON Schema, required fields, expected value types or API-specific rules. Use your application's schema validator to check those constraints.

Can I format large JSON files?

Browser memory and device performance set practical limits. For very large documents, use a trusted local editor or command-line JSON tool and avoid loading sensitive data into an online service.
